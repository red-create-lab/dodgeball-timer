# Dodgeball Timer

クロスドッジボール専用の試合タイマー。ビルド不要の単一HTMLファイルで、GitHub Pagesでそのまま公開して使っている。

公開URL: `https://red-create-lab.github.io/dodgeball-timer/`(リポジトリ: `red-create-lab/dodgeball-timer`)

## 技術スタック / 構成

- Vanilla HTML + CSS + JavaScript のみ。フレームワーク・ビルドツール・外部ライブラリなし。
- 外部リソースの読み込みも一切なし(フォントもシステムフォント指定のみ)。オフライン・Wi-Fiなしの会場でも動作する。
- ファイルは基本的に **`index.html` 1ファイルで完結**。JSは同ファイル末尾の `<script>` 内にIIFEでまとめて書かれている。

```
index.html        ← 公開されている実体(GitHub Pagesはこれをルートとして配信)
クロスドッジボールタイマー_vX.X.html  ← index.html と同一内容のバージョン記録用コピー
CHANGELOG.md       ← 変更履歴
```

`index.html` とバージョン番号付きファイルは常に同じ内容。更新するときは両方を同時に更新し、`CHANGELOG.md` にも1行追記する(過去のバージョンファイルは削除せず残す運用)。

## デプロイ方法

GitHub Pages (Settings → Pages → Deploy from a branch → `main` / `root`) で配信しているだけ。`index.html` をリポジトリ直下に置き換えてコミットすれば、数分で公開URLに反映される。ビルドステップは存在しない。

## 画面構成

1. **設定画面** (`#setup-screen`) — チーム名・ロゴ画像(任意)・ゲームタイム・セットタイム・最終セット短縮ルール・前後半の有無を入力し、「この内容で試合を開始」で試合画面へ遷移。
2. **試合画面** (`#main-screen`) — ゲームタイム(大表示)・セットタイム(リング表示)・両チームのスコア/WINボタンを表示。右上のハンバーガーメニュー(☰)に「セット履歴」「直前の判定を取り消す」「試合をリセット」を格納。

画面遷移はCSSクラス `.screen.active` の付け外しのみで、SPA的なルーティングは無い(1ページ内に2画面分のDOMが常に存在)。

## コアロジック(状態管理)

グローバルな `state` オブジェクト1つで全状態を管理している(フレームワークのstate管理は無し、DOM操作も直接 `document.getElementById` で行う素朴な作り)。主なポイント:

### ゲームタイムとセットタイムの連動
- `state.running` フラグが真の間だけ、`setInterval`(100ms間隔)でゲームタイム・セットタイムの両方が同時にカウントダウンされる。
- 「セット開始」ボタンを押した瞬間に両方の `xxxEndAt`(Date.now() + 残り時間)を設定し直して再開する設計。**ゲームタイムは、セットが進行している間だけ進む**(セット間の待機中や一時停止中は止まる)仕様が要件のため、単純な1本のタイマーではなく2つの残り時間を同時に進めている点に注意。

### 最終セット判定
- `computeNextSetDuration()` が、残りゲームタイムと「最終セット短縮ルール」の設定値から、次のセットが通常セットか最終セットか、そして何分にするかを毎回計算する。
- `setIsFinal` が真のセットが終了すると、そのまま `finishHalf()` が呼ばれて前半/試合終了になる(=最終セットは1つだけ、という前提)。

### 判定(WIN/引き分け)の確定フロー
- セットタイム0になっても自動では確定させず、`state.awaitingDecision = true` にして停止し、ユーザーがWIN/引き分けボタンのいずれかを押すまで待つ。
- スコア加算ロジック: **WINボタンを押したチームにそのまま加点**(2点)。引き分けは両者+1点。過去に「押した側と逆のチームに加点」というバグがあった箇所なので、ここを触るときは要注意。

### 取り消し機能(undo)
- `endSet()` の冒頭で、判定確定前の状態を丸ごと `state.lastSnapshot` に保存している。
- 「直前の判定を取り消す」は、この1個前のスナップショットに戻すだけの単純な実装。**取り消せるのは直前の1件のみ**(2手先には戻せない)。次のセットを開始するとスナップショットは破棄される。

### 前半→後半の移行
- 前半が終わると「前半終了」ボタンが表示される(押せる状態)。
- 1回目のクリックでボタン文言が「後半へ進む」に変わるだけ(`state.confirmingNextHalf` フラグ)。2回目のクリックで確認ダイアログを出し、OKで `goToSecondHalf()` が実行される。**2段階クリックが必須の意図的な仕様**(誤操作防止)。

## 既知の制約・注意点

- **永続化なし**: `localStorage` 等は使っていない。ページをリロードするとスコア・履歴は全て消える(「試合をリセット」ボタンも中身は単なる `location.reload()`)。
- **チームロゴ画像**: `FileReader` でdata URLに変換してその場でメモリ上に保持しているだけ(`state.teamALogo` / `teamBLogo`)。ファイルとして保存されるわけではなく、リロードすると消える。
- **音**: Web Audio APIで単純なビープ音を鳴らしているだけ(外部音源ファイルなし)。iOSでは初回のユーザー操作(タップ)がないと `AudioContext` が鳴らないブラウザ制約があるので注意。
- **バリデーションはほぼ無い**: 分・秒の入力欄に負数や極端な値を入れても弾かれない。運用上、大会本番の直前に主催者が入力する想定のため簡素にしてある。
- **1ファイル完結が意図的な設計方針**: モジュール分割やビルドツール導入は今のところ想定していない(会場でオフライン動作させる要件と、非エンジニアが直接ファイルを差し替えて運用する前提のため)。分割する場合は、この制約(単一ファイルで配布・GitHub Pagesにそのまま置くだけ)を崩さないか要検討。

## 引き継ぎ時の運用ルール

- バージョンを上げるときは、`index.html` とバージョン番号付きファイルを両方更新し、`CHANGELOG.md` に変更点を追記する。
- GitHubへのコミット時、コミットメッセージにも変更内容を一言添える運用にしている。
- 過去バージョンのファイルは削除せず、リポジトリに残しておく(簡易的な変更履歴として)。
